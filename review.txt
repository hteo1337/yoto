1. **[P2, blocking] Reclaim interrupted import scratch during startup recovery.** `selfhost/shims/storage.ts:22-32` changes a nonterminal import to an error but never removes its `/tmp/yoto/import-<id>` directory. `compose.yaml:28-30` deliberately persists that directory in the scratch volume. Once the record is terminal, no workflow is scheduled to execute `selfhost/shims/sandbox.ts:96-107` cleanup; new requests receive new UUIDs. Restarting during a large download or chapter split therefore leaves audio/partials permanently allocated. Repeated interrupted imports can fill the persistent volume and prevent subsequent downloads and progress writes. This is distinct from the intentionally retained, small terminal progress JSON records.

Differing control in the same run: ordinary `sandbox.destroy()` removed its directory, while an outside sentinel survived. Recover/delete scratch belonging to validated interrupted import IDs before forgetting the unfinished work; preserve terminal replay records and unrelated paths.

2. **[P2, observed portability issue; Linux impact unverified] Output-limit termination can throw outside the exec promise.** `selfhost/shims/sandbox.ts:16-23,54-70` rethrows kill errors other than ESRCH from a stdout/stderr event callback. Handle termination failures inside the exec lifecycle rather than throwing from EventEmitter callbacks. Retained output stayed <=8 MiB; the small-output control succeeded.
